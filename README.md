# 🛡️ SecureMesh Testbed

Welcome to the **SecureMesh Testbed**! This project has evolved from a standard IoT honeypot into a **research-oriented cybersecurity testbed** designed for investigating AI-based adaptive defense under uncertainty.

At its core, SecureMesh formulates the interaction between an attacker and a defender as a **Bayesian Markov game**. It allows researchers to simulate network topologies, vulnerable IoT services (like ESP32/ESP8266), and intrusion detection systems (IDS) in a reproducible, software-only environment. 

Our goal is to answer a critical research question: *How can a defender make effective adaptive security decisions when the capabilities and behavior of an AI-based attacker are uncertain?*

---

## ✨ Key Features

- **🧠 AI vs. AI Simulations**: Pit different types of agents against each other:
  - **Attackers**: `RandomAttacker`, `ScriptedAttacker` (kill-chain approach), and `RLAttacker` (adaptive PPO).
  - **Defenders**: `StaticDefender` (fixed heuristics), `MLDefender` (Random Forest), and `RLDefender` (adaptive PPO).
- **🕵️ Bayesian Belief Tracking**: The RL Defender maintains and dynamically updates a probability distribution over the attacker's type (opportunistic, sophisticated, stealthy) based on observed behavior.
- **🏗️ Realistic IoT Simulation**: Simulated ESP8266 and ESP32 endpoints that mimic real-world vulnerabilities (MQTT, CoAP, OTA, and credential-capture surfaces) without requiring physical hardware.
- **📊 Comprehensive Evaluation Framework**: Built-in metrics (Attack Success Rate, Detection Rate, System Resilience, Adaptation KL Divergence), structured logging, and automated Matplotlib visualizations.
- **💻 Modern React Dashboard (WIP)**: A frontend for visualizing experiment results, reward curves, and belief evolution.

## 🏗️ Architecture & Project Structure

The repository is organized into the following main components:

- **`securemesh_testbed/`**: The core Python package containing the simulated environment and agents.
  - **`agents/`**: Implementations of various attacker and defender agents, including a lightweight NumPy-only PPO implementation (`ppo_agent.py`).
  - **`environment/`**: Core network simulators, IDS engines, and IoT firmware mocks (`iot_sim.py`, `network_sim.py`).
  - **`game/`**: The Gymnasium-compatible Markov game formulation (`markov_game.py`) and action spaces.
  - **`experiments/`**: CLI runners and scenario definitions (e.g., known attacks vs. zero-day).
  - **`evaluation/`**: Metrics computation, structured logging, and plotting utilities.
- **`frontend/` (React + Vite)**: A modern dashboard built with React and TailwindCSS to visualize the experiment results generated by the testbed.
- **`backend/` (FastAPI)** & **`esp8266/` (C++)**: Legacy components from the original honeypot implementation (preserved for reference/future integration).

## 🚀 Getting Started

### Prerequisites

- Python 3.10+
- Node.js (for the frontend dashboard)

### 1. Install the Testbed

We recommend using a virtual environment. The testbed relies on lightweight dependencies like NumPy and Gymnasium (no heavy PyTorch requirement!).

```bash
cd securemesh_testbed
pip install numpy gymnasium matplotlib pandas scikit-learn tabulate
```

### 2. Run an Experiment

You can run a simulated experiment right from the CLI. Let's pit a scripted kill-chain attacker against an adaptive RL defender:

```bash
python -m securemesh_testbed.experiments.run_experiment \
    --scenario known_attacks \
    --attacker scripted \
    --defender rl \
    --episodes 50 \
    --seed 42 \
    --output securemesh_testbed/results/my_first_experiment
```

The experiment runner will execute the Markov game, train the RL agents if applicable, and generate a suite of CSV logs and PNG plots in the specified output directory.

### 3. Explore the Results

Navigate to the output directory to view the generated plots, such as:
- `reward_curves.png`: Compares attacker and defender cumulative rewards over time.
- `belief_evolution.png`: Shows how the defender's Bayesian belief about the attacker type evolves during an episode.
- `detection_rate.png` & `service_availability.png`.
